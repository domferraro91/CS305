# CS305
Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?\
My client was Artemis Financial, a financial services company that needed to improve the security of its software application. The company wanted to protect sensitive information, reduce security risks, and ensure that data could be transmitted and verified securely. My task was to review the application for potential vulnerabilities, improve its security, and implement a secure checksum using the SHA-256 hashing algorithm. The project also involved supporting secure HTTPS communication and following secure coding practices.

What did you do well when you found your client’s software security vulnerabilities? Why is it important to code securely? What value does software security add to a company’s overall well-being?\
One thing I did well was focus on identifying security weaknesses and understanding how secure coding practices could reduce risk. I worked on implementing SHA-256 hashing to generate a checksum that could help verify data integrity. I also considered the importance of using secure communication and reviewing software dependencies for known vulnerabilities.

Secure coding is important because vulnerabilities can expose sensitive information, allow unauthorized access, and damage a company's reputation. Strong software security helps protect customers, maintain trust, reduce the likelihood of costly incidents, and support the company's long-term success.

Which part of the vulnerability assessment was challenging or helpful to you?\
One challenging part of the assessment was troubleshooting errors after making code changes. For example, compatibility issues between Java versions and the code being used can prevent an application from compiling or running correctly. This experience showed me that security improvements must be tested carefully and that an error should be investigated rather than ignored. The assessment was helpful because it encouraged me to examine the application more closely and understand how development tools can help identify and resolve potential problems.

How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?\
I increased the application's security by using SHA-256 to create a checksum, considering HTTPS for encrypted communication, and reviewing dependencies for known vulnerabilities. These measures provide different types of protection: hashing supports integrity verification, HTTPS helps protect data in transit, and dependency analysis can identify risks in third-party libraries.

In future projects, I would use tools such as OWASP Dependency-Check to identify vulnerable dependencies and static analysis tools to find potential coding weaknesses. I would also consult the OWASP guidance and the severity of each finding to prioritize mitigation. I would consider the likelihood of exploitation, the potential impact, and the business requirements before selecting a mitigation technique.

How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?\
To ensure that the application remained functional, I would compile the project, run the application, and test the checksum endpoint. I would verify that it returned the expected output and that the checksum remained consistent for the same input. I would also confirm that HTTPS was configured correctly and review any warnings or errors produced during testing.

After refactoring, I would run the available vulnerability scans again and compare the results with the original findings. I would review dependency versions, examine the updated code, and test the application for regressions. These steps help determine whether the changes introduced new issues. If testing reveals compilation errors or unexpected behavior, I would resolve those problems before considering the work complete.

What resources, tools, or coding practices did you use that might be helpful in future assignments or tasks?\
The tools and practices I can carry forward include Java, Spring Boot, Maven, HTTPS configuration, SHA-256 hashing, and dependency vulnerability scanning. I also learned the importance of using clear and maintainable code, handling errors appropriately, and testing changes incrementally. Reviewing compiler output and application logs is especially useful when troubleshooting problems. In future assignments, I can apply these practices to identify security risks earlier and make software more reliable.

Employers sometimes ask for examples of work that you have successfully completed to show your skills, knowledge, and experience. What might you show future employers from this assignment?\
I could show future employers the refactored Java source code, the implementation of the SHA-256 checksum endpoint, my security assessment report, and screenshots documenting successful testing. I could also explain how I approached vulnerability identification, considered multiple layers of security, and investigated issues encountered during development. Together, these materials would demonstrate my understanding of secure coding, basic application security testing, troubleshooting, and technical documentation. They would also provide an example of how I approach a software problem methodically and consider both functionality and security.
